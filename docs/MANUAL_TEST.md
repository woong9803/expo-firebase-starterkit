# 수동 테스트 가이드

Phase 1~10 구현 완료 기준 전체 기능 검증 체크리스트.
테스트 전 아래 준비사항을 먼저 확인할 것.

---

## 사전 준비

- `npx tsc --noEmit` → 타입 오류 0개 확인
- Firebase 콘솔 접속 → Auth / Firestore / Storage / Functions 전부 활성 상태 확인
- `npx expo start --ios` 또는 실기기 연결
- 테스트용 계정 4개 미리 준비 (admin / 선생님 / 학생 / 학부모)
- FCM 테스트는 실기기 필수 (시뮬레이터 미지원)

---

## PART 1 — 인증 플로우

### 1-1. 앱 시작 화면

- 앱 아이콘 (웅깅 로고) 표시
- 앱 이름 "웅깅" + 서브타이틀 "Woongking" 표시
- 슬로건 텍스트 표시
- 기능 설명 카드 3개 표시 (숙제 제출 / 원터치 출결 / 출석부 엑셀)
- "시작하기" 버튼 탭 → 회원가입으로 이동
- "이미 계정이 있어요" 버튼 탭 → 로그인으로 이동

### 1-2. 로그인

- 카카오 / Google / Apple 소셜 버튼 3개 표시
- 로그인 성공 → 역할에 맞는 홈 화면으로 이동

### 1-3. 회원가입 (이메일)

- 스텝 인디케이터 1/4 표시
- 이메일 / 비밀번호 입력 → 다음 진행

### 1-4. 휴대폰 번호 입력

> ⚠️ APNs 인증서 미설정 시 임시 스킵 상태 — OTP 수신 불가할 수 있음

- 전화번호 입력 필드 + "인증번호 받기" 버튼
- 번호 입력 후 다음 화면 이동

### 1-5. OTP 인증

- 6칸 입력 UI 표시
- 숫자 입력 시 다음 칸 자동 이동
- 타이머 카드 + 카운트다운 + 프로그레스바 표시
- "번호 오류? 다시 입력하기" 탭 → 번호 입력 화면으로 복귀

### 1-6. 역할 선택

- 스텝 인디케이터 3/4
- admin / 선생님 / 학생 / 학부모 카드 4개 표시
- 카드 선택 시 보라색 테두리 + 우측 체크 표시
- 미선택 상태에서 "다음" 버튼 비활성 (회색)
- 선택 후 "다음" 버튼 활성 (보라색)

### 1-7. 코드 입력 (학생/선생님/학부모)

- 스텝 인디케이터 4/4
- 큰 코드 입력창 표시 (보라색 테두리, 큰 폰트)
- 올바른 코드 입력 → "✓ 올바른 코드예요" 표시
- 학원/반 정보 카드 표시 (Firestore 실데이터)
- "이 학원(반)에 참여하기" 탭 → 홈으로 이동
- 5회 오류 시 30초 재시도 대기 메시지 표시

### 1-8. admin 학원 등록

- 학원 유형 선택 (학원 / 교습소 / 개인과외)
- 학원명 / 대표자명 / 연락처 / 주소 입력
- 저장 후 Firestore `academies` 문서 `status: pending` 생성 확인
- 승인 대기 화면으로 이동

### 1-9. 승인 대기 화면 (admin)

- 아이콘 + 안내 문구 표시
- 신청 정보 카드 (학원명 / 대표자 / 연락처 — Firestore 실데이터)
- "카카오톡으로 문의" 버튼
- "미리 탐색해보기" 버튼 탭 → admin 홈으로 이동

## PART 2 — Admin 기능

> admin 계정으로 로그인 후 진행

### 2-1. 홈 탭

- 보라색 그라데이션 카드 표시
- 학원명 + admin 이름 + 알림 아이콘 표시
- 통계 2칸: 전체 학생 수 / 오늘 출석률 (Firestore 실데이터)
- 통계 3칸: 반 수 / 선생님 수 / 플랜 (Firestore 실데이터)
- 오늘 확인 필요 — 결석(빨간 박스) / 미입력(노란 박스)
- 반별 출석률 프로그레스바 카드
- 알림 아이콘 탭 → 알림함으로 이동

### 2-2. 숙제 탭

- 반별 숙제 목록 표시
- 숙제 카드에 D-Day 칩 표시
- 숙제 카드 탭 → 숙제 검사 화면으로 이동

### 2-3. 숙제 출제

> 숙제 탭 내 출제 버튼 또는 진입 경로로 접근

- 제목 / 내용 / 반 선택 / 마감일 입력
- 저장 후 숙제 목록에 즉시 반영
- 해당 반 학생 홈에 D-Day 카드 표시 확인

### 2-4. 숙제 검사

- 제출물 목록 (제출자 / 미제출자 구분)
- 제출 현황 프로그레스바 표시
- 사진 탭 → 확대 뷰어
- 좋아요(👍) / 다시해오기(💧) 피드백 버튼
- 피드백 저장 후 학생 홈 카드에 반영 확인
- 미제출 학생 알림 버튼 탭 → FCM 발송 (실기기에서 확인)
- 지각 제출 꼬리표 표시 확인

### 2-5. 출결 탭

- 반 선택 드롭다운
- 반별 학생 명렬표 표시
- 출결 현황 요약 (출석 N / 지각 N / 결석 N)

### 2-6. 출결 엑셀 내보내기

> 출결 탭 내 내보내기 버튼으로 접근

- 반 선택 + 월 선택 UI
- 내보내기 버튼 탭 → 파일 생성
- iOS: 공유 시트 표시 (파일로 저장 / 이메일)
- 생성된 엑셀 열기 → 법정 필수 항목 확인
  - 학원명 / 반 이름 / 담당 선생님 / 연월 헤더
  - 학생별 행: 성명 / 생년월일 / 보호자 연락처 / 교습과목 / 수강반 / 수강기간
  - 날짜별 출결 기호: ○ / △ / X
  - 월간 합계 (출석일수 / 지각 / 결석 / 출석률)
  - 파일명: `{반이름}_{연도}년_{월}월_출결현황.xlsx`
- 무료 플랜 계정 → Pro 전환 바텀시트 표시 확인

### 2-7. 학생 탭

- 반별 학생 목록 표시
- 학생 반 변경 기능
- 학생 퇴원 처리 → `is_active: false` → 목록에서 제거 확인

### 2-8. 공지 탭 + 작성

- 공지 목록 표시 (중요 공지 상단 고정)
- 공지 작성 화면 진입
  - 제목 / 내용 입력
  - 중요 공지 토글
  - 저장 후 목록에 즉시 반영
  - 중요 공지는 상단 고정 + 빨간 강조 표시 확인
- 공지 상세 탭 → 내용 표시 + 읽음 처리
- 공지 읽음 현황 화면
  - 읽음 수 + 프로그레스바
  - 미읽음 학생/학부모 목록

### 2-9. 설정 탭

- 학원 정보 카드 (보라 그라데이션) 표시
- 학원명 / 플랜 / 승인 상태 표시 (Firestore 실데이터)

**반 관리:**

- 반 목록 표시 (이름 / 담당선생님 / 학생 수 / 초대코드)
- "새 반 만들기" 탭 → 모달 오픈
  - 반 이름 / 교습과목 입력 → 만들기
  - 생성 후 목록에 즉시 반영
- 반 "설정" 버튼 탭 → 설정 모달 오픈
  - 반 이름 / 교습과목 수정 후 저장
  - 초대코드 표시 + "코드 재발급" 버튼
    - 재발급 탭 → 확인 다이얼로그 → 새 코드로 즉시 변경 확인
    - 기존 코드로 가입 시도 → 실패 확인
  - 담당 선생님 칩 선택/해제 토글
    - 선생님 칩 선택 → Firestore `assigned_class_ids` 업데이트 확인
    - 해당 선생님 홈에 반 즉시 반영 확인
  - "반 삭제" 탭 → 확인 다이얼로그 → 삭제 후 목록에서 제거

**선생님 관리:**

- 선생님 목록 + 담당반 수 표시
- 선생님 초대코드 표시 + 복사 버튼
- 선생님 삭제 → 비활성화 처리 확인

### 2-10. 영상 등록

- YouTube URL 입력
  - 올바른 URL → 썸네일 미리보기 자동 표시
  - 잘못된 URL → 빨간 테두리 + 오류 안내 문구
- 영상 제목 + 대상 반 선택
- 등록 완료 후 영상 목록에 표시 확인

## PART 3 — 선생님 기능

> 선생님 계정으로 로그인 후 진행

### 3-1. 홈 탭

- 보라색 그라데이션 카드 + 알림 아이콘 표시
- 통계 3칸: 미검사 숙제 수 / 오늘 결석 수 / 이번달 출석률 (실데이터)
- 담당 반 가로 스크롤 카드
- 숙제 검사 현황 카드 (D-Day 칩 + 프로그레스바)
- 최근 공지 카드 (좌측 세로바 + 읽음 프로그레스바)
- 데이터 없을 시 empty state 표시

### 3-2. 반 선택

- 담당 반 목록 표시
- 반 선택 후 홈 통계 데이터 변경 확인

### 3-3. 숙제 탭

- 숙제 목록 표시
- 숙제 출제 버튼 탭
  - 제목 / 내용 / 반 선택 / 마감일 설정
  - D-Day 자동 계산 표시
  - 저장 후 학생 홈 카드에 즉시 반영 확인
- 숙제 검사 화면 (2-4 항목과 동일)

### 3-4. 출결 탭

- 반 선택 → 학생 명렬표 표시
- 출결 요약 (출석 N / 지각 N / 결석 N)
- 출석 / 지각 / 결석 원터치 입력
  - 탭 시 즉시 Firestore 저장 확인
  - 같은 반을 다른 기기에서 열었을 때 실시간 반영 확인 (가능하면)
- 결석 입력 시 → 해당 학생 학부모에게 FCM 알림 발송 확인 (실기기)
- 오프라인 테스트:
  - 기기 네트워크 끊기
  - 오프라인 배너 표시 확인
  - 출결 입력 → 오류 없이 저장됨
  - 네트워크 재연결 → 자동 동기화 + 완료 토스트 표시

### 3-5. 출결 엑셀 내보내기

> 2-6 항목과 동일하게 검증

### 3-6. 공지 탭

- 공지 목록 표시 (중요 상단 고정)
- 공지 작성 (2-8 항목과 동일)
- 공지 읽음 현황 확인

### 3-7. 학생 탭

- 담당 반 학생 목록 표시
- 학생 직접 생성
  - 이름 / 학교 / 학년 입력
  - 생성 후 가상 이메일 자동 생성 확인 (`s_XXXXXX@dev-app-first.app`)
  - 임시 비밀번호 + 인쇄용 카드 UI 표시

### 3-8. 내정보 탭

- 이름 / 역할 / 학원명 표시
- 알림 설정 — 푸시 알림 통합 ON/OFF 토글
  - 토글 변경 후 Firestore `notif_prefs` 저장 확인
- 로그아웃 → 로그인 화면으로 이동

### 3-9. 알림함

- 알림 목록 표시 (읽음 / 미읽음 구분)
- 알림 탭 → 읽음 처리 + 해당 화면으로 딥링크 이동

### 3-10. 영상 등록

> 2-10 항목과 동일하게 검증

## PART 4 — 학생 기능

> 학생 계정으로 로그인 후 진행

### 4-1. 홈 탭

- 흰 헤더 + 인사말 + 이름 표시
- 우측 스트릭 뱃지 (연속 일수) 표시
- 초록 그라데이션 스트릭 카드 (막대 그래프 포함)
- 숙제 카드 상태별 확인:
  - D-0 카드 → 빨간 좌측바 + "지금 제출하기" 버튼
  - D-n 카드 → 보라 좌측바 + 마감까지 남은 날
  - 완료 카드 → 초록 테두리 + 피드백 텍스트
  - 재제출 필요 카드 → 💧 피드백 + 재제출 버튼
- 중요 공지 카드 하단 표시

### 4-2. 숙제 탭

- 미제출 / 검사대기 / 다시제출 / 완료 탭 전환
- 각 탭에 해당 숙제만 표시 확인
- D-Day 배지 표시

### 4-3. 숙제 제출

- 카메라 촬영 화면 진입
- 사진 촬영 → 미리보기 표시
- 최대 5장 제한 확인 (6장 시도 시 안내)
- 재촬영 버튼 동작
- 제출 탭 → Storage 업로드 + Firestore 저장
- 파일 크기 200KB 이하 압축 확인 (로그 또는 Storage 콘솔에서)
- 마감 전 제출 → `is_late: false` 확인
- 마감 후 제출 → `is_late: true` + 지각 꼬리표 표시 확인
- 재제출 시 → "이전 사진 교체" 다이얼로그 표시
- 오프라인 제출 테스트:
  - 네트워크 끊고 제출 시도
  - 임시저장 메시지 표시
  - 재연결 후 "이어서 제출하기" 다이얼로그 표시
  - 재시도 탭 → 정상 업로드 확인

### 4-4. 영상 탭

- 내 반에 등록된 영상 목록 표시 (썸네일 + 제목)
- 영상 카드 탭 → YouTube 앱 또는 브라우저로 이동
- 등록된 영상 없을 시 empty state 표시

### 4-5. 출결 탭

- 월간 캘린더 표시
- 출석(초록) / 지각(노랑) / 결석(빨강) 색상 구분
- 다른 달 이동 확인

### 4-6. 내정보 탭

- 이름 / 역할 / 반 이름 표시
- 알림 설정 — 숙제 알림 / 피드백 알림 / 공지 알림 각 토글
  - 토글 변경 후 Firestore `notif_prefs` 저장 확인
- 로그아웃

### 4-7. 스트릭 상세 화면

> 홈 스트릭 카드 탭으로 진입

- 최근 30일 막대 그래프 표시
  - 제출(초록) / 지각(노랑) / 미제출(빨강) / 숙제없음(회색) 색상
- 30일 통계 카드 (마감 전 제출 / 지각 / 미제출 일수 + 제출률)
- 스트릭 규칙 안내 카드
- 뒤로가기 버튼 동작

## PART 5 — 학부모 기능

> 학부모 계정으로 로그인 후 진행 (자녀 계정과 연동 필수)

### 5-1. 홈 탭

- 흰 헤더 + 자녀 탭 칩 표시 (활성: 주황색)
- 주황 그라데이션 출결 카드 (오늘 자녀 출결 상태)
- 오늘 숙제 — 미제출(빨간 카드) / 완료(초록 카드)
- 결석 시 사유 선택 칩 표시 (병원 / 가족행사 / 기타)
  - 칩 선택 → "선생님께 전송하기" 버튼 표시
  - 전송 탭 → 선생님 명렬표에 즉시 반영 확인

### 5-2. 자녀 전환

> 자녀 2명 이상 연동된 계정으로 테스트

- 자녀 탭 칩 탭 → 전환 화면 이동
- 자녀 목록 표시
- 다른 자녀 선택 → 홈 데이터 즉시 변경 확인

### 5-3. 자녀 추가 연동

- 자녀 연동코드 입력
- 유효한 코드 → 자녀 계정 연결 확인
- 연결 후 자녀 탭 칩에 즉시 반영

### 5-4. 숙제 탭

- 선택된 자녀의 숙제 목록 표시
- 숙제 카드 탭 → 자녀 숙제 상세 화면 이동
  - 제출물 이미지 표시
  - 선생님 피드백 표시
  - 뒤로가기 → 홈이 아닌 숙제 목록으로 이동 확인

### 5-5. 출결 탭

- 선택된 자녀의 출결 현황 표시
- 결석 사유 칩 선택 → 전송 (5-1 항목 참조)

### 5-6. 공지 탭

- 공지 목록 표시
- 공지 탭 → 읽음 처리 후 Firestore `read_by` 배열에 uid 추가 확인
- 중요 공지 강조 표시

### 5-7. 내정보 탭

- 이름 / 역할 표시
- 알림 설정 — 숙제 알림 / 출결 알림 / 공지 알림 각 토글
  - 토글 변경 후 Firestore `notif_prefs` 저장 확인
- 로그아웃

## PART 6 — 크로스 역할 연동 테스트

> 두 역할을 동시에 사용하여 데이터 연동을 검증

### 6-1. 숙제 전체 사이클

- **선생님** 숙제 출제 → **학생** 홈에 즉시 D-Day 카드 표시

- **선생님** 피드백 등록 → **학생** 홈 카드에 피드백 텍스트 반영
- **학부모** 자녀 숙제 상세에서 제출물 + 피드백 확인 가능

### 6-2. 출결 연동

- **선생님** 결석 입력 → **학부모** 홈 출결 카드에 즉시 반영
- **학부모** 결석 사유 전송 → **선생님** 명렬표에 사유 즉시 표시

### 6-3. 공지 연동

- **선생님** 공지 작성 → **학생** / **학부모** 공지 탭에 즉시 표시
- **학생** 공지 읽음 처리 → **선생님** 읽음 현황 수 증가 확인
- 중요 공지 → **학생** 홈 하단에 중요 공지 카드 표시 확인

### 6-4. 실시간 동기화

- 선생님 A기기에서 출결 입력 → 선생님 B기기에서 즉시 반영

### 9-1. 강제/권장 업데이트 체크

**사전 설정** — Firebase 콘솔 → Firestore → `app_config/version` 문서 생성:

```
min_version: "2.0.0"
latest_version: "2.0.0"
store_url_ios: "https://apps.apple.com"
store_url_android: "https://play.google.com"
```

- 앱 실행 → 강제 업데이트 다이얼로그 표시 확인
- 다이얼로그 닫기 불가 확인 (바깥 탭해도 닫히지 않음)
- "업데이트" 버튼 탭 → 스토어 앱 열림 확인

**권장 업데이트 확인** — `min_version: "1.0.0"`, `latest_version: "1.1.0"` 으로 변경:

- 앱 재실행 → 권장 업데이트 다이얼로그 표시
- "나중에" 버튼 탭 → 다이얼로그 닫히고 앱 정상 사용 가능
- "업데이트" 버튼 탭 → 스토어 앱 열림

**테스트 후 정리** — `min_version: "1.0.0"`, `latest_version: "1.0.0"` 으로 원복

### 9-5. Firestore Security Rules — 탈퇴 유저 접근 차단

> Firebase 콘솔 → Firestore → 규칙 탭 → "규칙 플레이그라운드"

**테스트 1 — 탈퇴 유저 차단 확인**:

1. 테스트용 uid의 `users/{uid}` 문서에 `deleted_at: Timestamp(현재시각)` 설정
2. 규칙 플레이그라운드:
  - 시뮬레이션 유형: `get`
  - 경로: `/databases/(default)/documents/notices/임의ID`
  - 인증: 해당 uid 선택
3. - [ ] 결과: **Deny** (거부) 확인

**테스트 2 — 정상 유저 허용 확인**:

1. 같은 uid의 `users/{uid}.deleted_at` 을 `null` 로 변경
2. 동일한 규칙 플레이그라운드 재실행
3. - [ ] 결과: **Allow** (허용) 확인

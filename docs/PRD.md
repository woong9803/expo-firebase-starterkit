## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 앱 이름 | dev-app-first (출시 전 확정 예정) |
| 미션 | 선생님 퇴근 시간을 앞당기고, 학원 이탈률을 방어한다 |
| 첫 파일럿 | 본인 근무 학원 (학생 100명 이상, 카톡 단톡방 대체) |

| 마케팅 전략 | 파일럿 → 레퍼런스 데이터 → 커뮤니티 후기 → 학원 박람회 |

## 2. 기술 스택

### 앱 (React Native)

| 기술 | 용도 | 선택 이유 |
|------|------|----------|
| React Native | iOS + Android 동시 개발 | 하나의 코드로 두 플랫폼 지원 |
| Expo | 네이티브 기능 간편화 | 카메라·알림 등 별도 설정 없이 바로 사용 가능 |
| expo-router | 파일 기반 라우팅 | 역할별 화면 분리 (admin / teacher / student / parent) |
| TypeScript (strict) | 정적 타입 언어 | 버그 사전 방지, 코드 안정성 |
| Zustand | 전역 상태관리 | Redux보다 가벼움 — 로그인 유저·선택 반 관리 |

### 백엔드 — Firebase

| 서비스 | 용도 | 비고 |
|--------|------|------|
| Firebase Auth | 이메일/비번 + 소셜 로그인 + 역할 분기 | admin · 선생님 · 학생 · 학부모 |
| Firestore | 실시간 DB — 출결 즉시 동기화 | NoSQL · 실시간 리스너 · 서브컬렉션 구조 |
| Firebase Storage | 숙제 사진 업로드 저장 | 업로드 전 클라이언트 압축 필수 (200KB 이하) |
| FCM | 푸시 알림 | 숙제 마감 · 피드백 · 미제출 자동 알림 |
| Cloud Functions | 카카오 소셜 로그인 서버 처리 | 카카오 Admin Key 보안 격리 |
| Firebase Crashlytics | 앱 크래시 자동 수집 | 파일럿 버그 모니터링 |

> **Supabase 대신 Firebase 선택 이유:** 실시간 출결 동기화(Firestore)가 킬러 기능이며, FCM 푸시 알림 내장, SQL 없이 바로 사용 가능. 규모 확장 시 Supabase 마이그레이션 고려 예정.

## 3. Firestore 데이터 구조

> `submissions`, `records`는 서브컬렉션으로 분리 — 문서 1MB 제한 회피 및 쿼리 효율화
> `academy_id` 최상위 분리 구조 — 추후 다중 학원 확장 시 데이터 혼재 방지

### academies/{academyId}

```
{
  name: string,
  created_at: Timestamp,
  plan: 'free' | 'pro' | 'trial',
  trial_ends_at: Timestamp | null,
  status: 'pending' | 'active' | 'rejected',
  academy_type: '학원' | '교습소' | '개인과외',
  submitted_at: Timestamp,
  approved_at: Timestamp | null,
  reject_reason: string | null,
  owner_name: string,
  owner_phone: string,
  address: string
}
```

### users/{uid}

```
{
  name: string,
  role: 'admin' | 'teacher' | 'student' | 'parent',
  academy_id: string,
  class_id: string | null,             // 학생 전용 — 소속 반
  assigned_class_ids: string[],        // 선생님 전용 — 본인이 직접 선택한 담당반 목록 (여러 개 가능)
  link_code: string | null,            // 학생 전용 6자리 연동코드
  children: string[],                  // 학부모 전용 — 자녀 uid 배열
  is_active: boolean,
  birth_date: string | null,           // 법정 출석부 대응 (신규)
  guardian_phone: string | null,       // 법정 출석부 대응 (신규)
  enrollment_date: Timestamp | null,   // 법정 출석부 대응 (신규)
  phone_number: string,
  phone_verified: boolean,
  deleted_at: Timestamp | null,        // 탈퇴 처리 시
  created_at: Timestamp
}
```

### classes/{classId}

```
{
  name: string,
  academy_id: string,
  invite_code: string              // 6자리 영숫자
}
```

> ★ `head_teacher_id` 제거 — 담당반은 선생님 문서의 `assigned_class_ids[]`로 관리
> ★ 특정 반의 담당 선생님을 조회할 때는 `users` 컬렉션에서 `assigned_class_ids` 배열에 해당 classId가 포함된 선생님을 쿼리

### homeworks/{homeworkId}

```
{
  title: string,
  content: string,
  class_id: string,
  due_date: Timestamp,
  created_by: string,              // 선생님 uid

  // 서브컬렉션: submissions/{studentUid}
  submissions/{studentUid}: {
    image_urls: string[],          // Storage URL 배열 (최대 5장)
    status: 'submitted' | 'checked',
    is_late: boolean,
    feedback: '👍' | '💧' | null,
    submitted_at: Timestamp
  }
}
```

### attendances/{classId_date}

```
{
  date: string,                    // 'YYYY-MM-DD'
  class_id: string,

  // 서브컬렉션: records/{studentUid}
  records/{studentUid}: {
    status: 'present' | 'late' | 'absent',
    reason: string | null          // 학부모가 입력한 결석 사유
  }
}
```

### notices/{noticeId}

```
{
  title: string,
  content: string,
  is_important: boolean,
  academy_id: string,
  read_by: string[],               // uid 배열
  created_at: Timestamp,
  created_by: string
}
```

### notifications/{notificationId}

```
{
  target_uid: string,
  type: 'homework_feedback' | 'homework_due' | 'attendance' | 'notice',
  title: string,
  body: string,
  is_read: boolean,
  created_at: Timestamp
}
```

### app_config/version

```
{
  min_version_ios: string,
  min_version_android: string,
  latest_version: string,
  force_update_message: string
}
```

## 4. 역할별 기능 명세

### admin (원장님)

| 기능 | 상세 설명 | 우선순위 |
|------|----------|---------|
| 학원 생성 및 설정 | 학원 이름, 선생님 초대, 전체 반 관리. 첫 번째 가입자 자동 admin 부여 | 필수 |
| 학생 비활성화 | 퇴원 시 isActive: false 처리. 데이터 유지, 앱에서 미노출 | 필수 |
| 전체 공지 발송 | 학원 전체 학생·학부모 대상 공지 작성 | 중요 |

> ★ admin은 더 이상 선생님에게 담당반을 직접 지정하지 않음. 선생님이 본인 담당반을 직접 선택.

### 선생님

| 기능 | 상세 설명 | 우선순위 |
|------|----------|---------|
| 담당반 설정 | 학원 내 전체 반 목록에서 본인 담당반을 직접 선택. 여러 개 선택 가능. 설정 화면에서 언제든 변경 가능 | 필수 |
| 홈 대시보드 | 미검사 숙제 수, 오늘 결석 수, 최근 공지 요약. 담당반 먼저 표시 | 필수 |
| 실시간 출결 명렬표 | 전체 반 접근 가능. 출석·지각·결석 원터치. Firestore 실시간 반영. 출석 요약 상단 표시 | 필수 |
| 숙제 출제 | 제목·내용·반·마감일 설정. D-Day 자동 계산. 전체 반 대상으로 출제 가능 | 필수 |
| 숙제 검사 + 피드백 | 제출물 갤러리 확인. 👍/💧 원터치 피드백. 미제출자 자동 목록. 지각 제출 꼬리표. 제출 현황 프로그레스 바 | 필수 |
| 공지사항 작성 | 중요/일반 구분. 읽음 확인 수 및 프로그레스 바 표시 | 필수 |
| 출결 엑셀 내보내기 | 반별·월별 선택 → 법정 출석부 양식 (.xlsx) 생성 → 파일 공유/저장 | 필수 |
| 반 관리 | 전체 반 접근 가능. 학생 반 이동은 admin·선생님만 가능. 반별 초대코드 표시 | 중요 |
| 미제출 자동 알림 | 마감 당일 오후 6시, 미제출 학생 학부모에게 FCM 자동 발송 | 중요 |
| 수업 영상 등록 | 유튜브 일부 공개 링크 등록 → 썸네일 카드 자동 변환. 비공개 링크 경고 처리 | 중요 |
| 학생 계정 직접 생성 | 선생님이 아이디·비밀번호 대신 생성해주는 시나리오 지원 | 중요 |

## 6. 온보딩 플로우

### 역할별 가입 방식

| 역할 | 가입 방법 | 입력값 | 활성화 |
|------|----------|--------|--------|
| admin (원장님) | 학원 만들기 선택 | 학원 이름 입력 | 운영 유형 선택 → 승인 대기 → 개발자 확인 후 활성화 + 학원코드 발급 |
| 선생님 | 선생님으로 가입 | 학원코드 입력 | 즉시 활성화 (승인 없음). 가입 후 담당반 직접 선택 |
| 학생 | 학생으로 가입 | 반 코드 입력 | 즉시 활성화 + 연동코드 6자리 자동 발급 |
| 학부모 | 학부모로 가입 | 자녀 연동코드 입력 | 즉시 자녀 계정과 연결 |

### 전체 가입 플로우

```
소셜/이메일 인증
  → 휴대폰 번호 입력 (Firebase Phone Auth, SMS OTP 6자리)
  → OTP 6자리 입력
  → 역할 선택 (admin / 선생님 / 학생 / 학부모)
  → 학원코드 / 반코드 입력 (역할에 따라)
  → [선생님만] 담당반 선택 (전체 반 목록에서 여러 개 선택 가능, 건너뛰기 가능)
  → 가입 완료
```

### 소셜 로그인

| 제공자 | 구현 방식 | 난이도 | 비고 |
|--------|----------|--------|------|
| 카카오 | 카카오 SDK → 액세스 토큰 → Cloud Functions → Firebase Custom Token | 중간 | 사전 등록 작업 필요 |
| Google | Google Sign-In SDK → Firebase Auth 직접 연동 | 낮음 | Firebase 네이티브 지원 |
| Apple | expo-apple-authentication → Firebase Auth 연동 | 낮음 | iOS 앱스토어 정책 필수 |

**소셜 로그인 주의사항:**
- 동일 이메일로 이메일 가입 + 소셜 로그인 시도 시 → "기존 방식으로 로그인 후 설정에서 소셜 계정을 연결할 수 있어요" 안내
- Apple 이메일 숨기기 선택 시 → privaterelay 가상 이메일 수신, `users/{uid}`에 그대로 저장
- 카카오 Admin Key는 Cloud Functions 환경변수로만 관리 — 클라이언트 코드 노출 금지
- Apple 로그인 — 이름·이메일은 최초 1회만 제공됨. 첫 로그인 시 반드시 Firestore에 저장

### 학생 계정 직접 생성 (이메일 없는 학생 대응)

| 항목 | 내용 |
|------|------|
| 이메일 처리 | 가상 이메일 자동 생성: `s_{6자리랜덤코드}@dev-app-first.app` |
| 비밀번호 | 선생님이 임시 비밀번호 설정 (예: 학생 생년월일 6자리) |
| 생성 완료 후 | '인쇄하기' 또는 '캡처용 카드' 버튼 제공 — 종이로 학생에게 배부 가능 |
| 이메일 변경 | 학생 설정 → 실제 이메일 입력 + 인증 → 가상 이메일 대체 (선택) |

### 휴대폰 인증

| 항목 | 내용 |
|------|------|
| 적용 대상 | 전 역할 — 이메일·카카오·Google·Apple 로그인 구분 없이 모두 필수 |
| 인증 방식 | Firebase Phone Auth — SMS OTP 6자리. 해외번호 지원 |
| 비용 | Firebase 무료 티어: 월 10,000건 무료. 학원 100명 기준 여유 충분 |
| Firestore 저장 필드 | `users/{uid}.phone_number` · `phone_verified: true` |
| 중복 번호 처리 | 동일 번호로 기존 계정 존재 시 → "이미 가입된 번호예요. 로그인해주세요" 안내 |

#### 화면 구성 (2단계 분리)

휴대폰 인증은 2개의 독립 화면으로 구성한다.

| 화면 | 파일 | 역할 |
|------|------|------|
| PhoneInputScreen | `app/(auth)/phone-input.tsx` | 휴대폰 번호 입력 → "인증번호 받기" 버튼 → `phone-verify`로 이동 |
| PhoneVerifyScreen | `app/(auth)/phone-verify.tsx` | OTP 6자리 입력 → 타이머 → "인증 확인" 버튼 → `role-select`로 이동 |

- `phone-input` → `phone-verify` 전환 시 전화번호를 route param으로 전달
- "번호 오류? 다시 입력하기" 누르면 `phone-input`으로 복귀

### 학원 인증 정책 (admin 가입 전용)

| 항목 | 내용 |
|------|------|
| 신청 정보 | 운영 유형 선택 (학원 / 교습소 / 개인과외) / 학원명 / 대표자명 / 연락처 / 주소 |
| 가입 직후 상태 | `status: pending` — 학원코드 미발급, 기능 제한 상태 |
| 개발자 확인 방법 | 파일럿 단계: 카카오톡 직접 확인 후 Firestore status 수동 변경 |
| 승인 시 | `status: active` + 학원코드 자동 발급 + admin에게 FCM 알림 |
| 반려 시 | 반려 사유 안내 + 계정 삭제 처리 |
| 미승인 자동 처리 | 30일 이내 승인 없으면 자동 비활성화 → 7일 유예 후 데이터 완전 삭제 |

**미승인(pending) 상태에서의 기능 제한:**

| 기능 | 미승인 상태 제한 |
|------|---------------|
| 학생 등록 | 최대 3명까지만 허용 |
| 선생님 초대 | 불가 |
| 반 생성 | 1개까지만 허용 |
| Pro 플랜 전환 | 불가 (승인 후 가능) |
| 출결·숙제·공지 | 3명 범위 내에서 사용 가능 |

> Security Rules에서 `academies.status` 체크 → 미승인 학원의 초과 등록 차단
> 미승인 계정 학생 3명 제한은 앱·웹 모두 동일하게 적용

### 반 변경 플로우

1. 선생님 또는 admin이 학생 선택 후 반 이동 처리
2. Firestore `users/{uid}.class_id` 필드 업데이트
3. 학생·학부모 앱 실시간 자동 갱신 — 새로고침 불필요
4. 학생이 직접 반 코드 재입력으로 반 변경하는 것은 보안상 허용하지 않음

## 7. 핵심 기능 상세 스펙

### 7-1. 숙제 스캔 제출

| 항목 | 내용 |
|------|------|
| 사용 라이브러리 | expo-camera + expo-image-manipulator + react-native-document-scanner-plugin |
| 엣지 감지 | 문서 모서리 자동 인식 및 파란 테두리 표시 |
| 원근 보정 | 기울어진 각도 자동으로 평평하게 보정 |
| 색상 처리 | 기본 흑백 변환. 컬러 유지 토글 옵션 제공 (미술·체육 등 대응) |
| 자동 압축 | 업로드 전 클라이언트 압축 — 목표 200KB 이하 (평균 90% 절감) |
| 다중 촬영 | 최대 5장까지 한 번에 제출 가능 |
| 미리보기 | 촬영 후 미리보기 확인 및 재촬영 가능 |
| 마감 판단 | `serverTimestamp()` 기준 — 클라이언트 시간 조작 방지 |

> 구글 드라이브 스캔은 Android 전용이라 iOS 지원 불가. Expo 내장 카메라로 직접 구현.

### 7-2. 실시간 출결 관리

- Firestore 실시간 리스너(`onSnapshot`)로 명렬표 실시간 동기화
- 출석(○) / 지각(△) / 결석(✕) 원터치 입력
- 출석 요약 카운터 상단 표시 (출석 N / 지각 N / 결석 N)
- 학부모가 결석 사유 칩([병원] [가족행사] [기타]) 선택 시 선생님 명렬표 실시간 반영
- 모든 선생님이 학원 내 전체 반 출결에 접근 가능. 담당반 여부와 무관.

### 7-3. 출결 엑셀 내보내기 (법정 출석부 양식)

**법적 근거:** 학원의 설립·운영 및 과외교습에 관한 법률 시행규칙 [별표 2] — 수강생 관리대장 및 출석부 의무 비치

**법정 필수 기재항목 vs. Firestore 현황:**

| 법정 항목 | Firestore 필드 | 현황 |
|---------|--------------|------|
| 수강생 성명 | users.name | 있음 |
| 생년월일 | users.birth_date (신규 추가) | 추가 필요 |
| 보호자 성명·연락처 | users.guardian_phone (신규 추가) | 추가 필요 |
| 교습과목·수강반 | classes.name | 있음 |
| 수강기간 (시작일~종료일) | users.enrollment_date (신규 추가) | 추가 필요 |
| 날짜별 출결 상황 | attendances/{classId_date}/records | 있음 |
| 결석 사유 | attendances.records.reason | 있음 |

**엑셀 파일 구성:**
- 헤더: 학원명 / 반 이름 / 담당 선생님 / 해당 연월
- 학생별 행: 번호 / 성명 / 생년월일 / 보호자 연락처 / 교습과목·수강반 / 수강기간
- 날짜별 출결: 출석(○) / 지각(△) / 결석(✕) / 휴원(-)
- 결석 사유: 학부모가 앱에서 입력한 사유 반영
- 월간 합계: 출석일수 / 지각 / 결석 / 출석률 (수식 자동 계산)

| 항목 | 내용 |
|------|------|
| 접근 권한 | admin · 선생님만 가능 |
| 내보내기 단위 | 반별 + 월별 선택 |
| 파일명 | `초등A반_2026년_3월_출결현황.xlsx` (자동 지정) |
| 사용 라이브러리 | xlsx (SheetJS) + expo-sharing + expo-file-system |
| 서버 비용 | 없음 (클라이언트에서 파일 생성, Storage 업로드 없음) |
| iOS 공유 방식 | '파일로 저장' 또는 '이메일로 보내기' |
| Android 공유 방식 | 다운로드 폴더 저장 또는 공유 시트 |

### 7-4. 스트릭 로직

| 상황 | 결과 |
|------|------|
| 숙제 있는 날 + 마감 전 제출 | 🔥 스트릭 유지 |
| 숙제 있는 날 + 미제출 | 스트릭 초기화 (0일) |
| 숙제 있는 날 + 지각 제출 | 스트릭 초기화 (0일) |
| 숙제 없는 날 | 그냥 넘어감 (카운트 무시) |

- `submissions`에서 `isLate: false`인 제출만 스트릭 카운트에 포함
- 학생 화면에 '마감 전 제출한 날 기준 · 지각 제출 시 초기화' 안내 문구 표시 필수
- 스트릭 시각화: 최근 30일치 막대 그래프로 표시

## 8. Firebase Security Rules 방침

### 핵심 원칙

- Firestore Security Rules — 역할별 접근 가능한 컬렉션 제한, `academyId` 기반 필터링
- Storage Rules — 인증된 사용자만 접근 가능한 signed URL 방식. 숙제 사진 공개 URL 금지
- 클라이언트 조건부 렌더링만으로 권한 제어 불충분 — Rules 레벨에서 반드시 처리
- Pro 기능: Security Rules에서 `academies.plan` 체크 — 클라이언트 우회 완전 차단
- 학원 미승인: Security Rules에서 `academies.status` 체크 — 초과 등록 차단

### 인증 보안

- 이메일 인증 가입 시 이메일 인증 필수
- 비밀번호 최소 8자 이상 강제
- admin 계정 2단계 인증(2FA) 권장
- 학생이 직접 반 코드 재입력으로 반 변경 불가 처리
- 마감 시간 판단은 `serverTimestamp()` 기준 — 클라이언트 시간 조작 방지
- 코드 입력 5회 연속 오류 시 30초 재시도 대기 (브루트포스 방지)

### 개인정보

- 수집 최소화 — 이름·이메일·역할·반·생년월일·보호자 연락처만 필수. 주민등록번호·주소 수집 안 함
- 만 14세 미만 아동은 법정대리인(학부모) 동의 필수
- 개인정보처리방침 페이지 출시 전 필수 작성
- Firebase 환경변수(.env) 분리 — 코드에 키 하드코딩 금지
- 카카오 Admin Key는 Cloud Functions 환경변수에만 저장 — 클라이언트(앱) 코드에 절대 포함 금지

## 9. 예외처리 및 오프라인 대응

### 9-1. 에러/예외 처리 시나리오

**사진 업로드 실패 시:**
- 업로드 중 네트워크 끊기면 → 로컬 임시저장 후 '재시도' 버튼 노출
- 3회 재시도 실패 시 → '나중에 다시 시도해주세요' 토스트 + 임시저장본 유지
- 앱 재실행 시 임시저장본 감지 → '이전에 저장된 사진이 있어요. 이어서 제출할까요?' 다이얼로그

**코드 입력 오류 시:**
- 학원 코드 / 반 코드 / 연동 코드 오류 → '코드를 다시 확인해주세요' (존재 여부 노출 금지 — 보안)
- 5회 연속 오류 시 → 30초 재시도 대기 (브루트포스 방지)

**중복 제출 처리:**
- 같은 숙제에 재제출 시 → '이미 제출한 숙제예요. 다시 제출하면 이전 사진이 교체돼요.' 확인 다이얼로그
- 마감 후 재제출 시도 → 지각 제출 안내 후 덮어쓰기 (`isLate: true` 유지)
- Firestore 구조: `submissions/{studentUid}` 단일 문서 덮어쓰기 방식 (버전 관리 없음 — MVP 범위)

### 9-2. 오프라인 대응 전략

**기본 방침:** Firestore 오프라인 캐시 활성화 (`enableIndexedDbPersistence`)

| 기능 | 오프라인 허용 | 비고 |
|------|------------|------|
| 출결 입력 | 허용 | 재연결 시 자동 동기화 |
| 숙제 목록 조회 | 허용 | 마지막 캐시 기준 |
| 공지사항 조회 | 허용 | 마지막 캐시 기준 |
| 숙제 사진 제출 | 불가 | 네트워크 필수 (Storage 업로드) |
| 푸시 알림 수신 | 불가 | FCM 특성상 온라인 시 수신 |

- 오프라인 상태 → 상단 배너 '오프라인 상태예요. 일부 기능이 제한돼요.' 노출
- 재연결 시 배너 자동 사라짐 + 동기화 완료 토스트
- 출결 오프라인 입력 후 재연결 시 → Firestore 자동 병합 (충돌 시 마지막 write 우선)

### 9-3. 학부모 알림 수신 거부 처리

- Firestore `notifications` 컬렉션에 알림 히스토리 항상 저장
- OS 알림 꺼도 앱 내 인박스에서 확인 가능
- 권한 요청 타이밍: 첫 로그인 완료 직후 → 거부 시 3일 후 1회 재요청, 이후 강제 없음

### 9-4. 탈퇴/데이터 삭제 정책

| 역할 | 삭제 범위 | 보존 항목 |
|------|----------|----------|
| 학생 | users 문서, submissions 전체 | 없음 |
| 학부모 | users 문서 | 없음 |
| 선생님 | users 문서 | 작성한 숙제·공지는 익명 처리 ('탈퇴한 선생님') |
| admin | 탈퇴 불가 | 먼저 다른 admin 지정 후 탈퇴 가능 |

- 탈퇴 신청 → '탈퇴하면 모든 데이터가 삭제돼요' 안내 다이얼로그
- 확인 → `is_active: false` + `deleted_at` 타임스탬프 기록 → 30일 유예 기간
- 30일 후 Cloud Functions 자동 완전 삭제
- 만 14세 미만: 법정대리인 동의 화면 별도 구현 필요

### 9-5. Pro 전환 UX 플로우

- 무료 기능 사용 중 Pro 전용 기능 진입 시도 → '이 기능은 Pro에서 사용할 수 있어요' 바텀시트
- 바텀시트: 기능 목록 + 가격 안내 (학생 수 기반 슬라이더) + '14일 무료 체험 시작' 버튼
- Firestore `academies/{academyId}.plan`: `free` | `pro` | `trial`
- Security Rules에서도 plan 체크 — 클라이언트 우회 방지
- 권장 방식: RevenueCat으로 iOS·Android 인앱결제 통합 관리. 웹 직접 결제 병행 가능

### 9-6. 반 코드 만료/재발급 정책

| 항목 | 내용 |
|------|------|
| 코드 구조 | 6자리 영숫자 (예: AB12CD). 위치: `classes/{classId}.invite_code` |
| 만료 기간 | 기본 없음 (상시 유효). 단, 재발급 기능 제공 |
| 재발급 권한 | admin 또는 담당 선생님만 가능 |
| 재발급 경고 | 기존 코드 즉시 무효화. '이미 가입한 학생에겐 영향 없어요' 안내 |
| 외부인 가입 시 대응 | admin이 학생 목록에서 이상 계정 발견 → 비활성화 → 코드 즉시 재발급 |

| 2단계 | 온보딩 + 역할별 라우팅 | 회원가입(이메일·카카오·Google·Apple) · 반 코드 입력 · 연동코드 생성 · role 기반 화면 분기 · 학생 계정 직접 생성 · 카카오 Cloud Functions 서버 함수 · admin 학원 인증 신청 플로우 · 선생님 담당반 선택 화면 |
| 3단계 (킬러) | 숙제 스캔 제출 + 검사 피드백 | 카메라 · 보정 · 압축 · 갤러리 검사 · 지각 처리 |
| 4단계 | 실시간 출결 관리 | 명렬표 · 결석 사유 선택 칩 · Firestore 실시간 동기화 |
| 4-1단계 | 출결 엑셀 내보내기 | SheetJS · 법정 출석부 양식 · expo-sharing · 4단계 완료 직후 바로 추가 |
| 5단계 | 공지사항 + 학부모 대시보드 | 읽음 확인 · 중요 공지 · 자녀 현황 실시간 · 앱 내 알림 인박스 |
| 6단계 | 푸시 알림 (FCM) | 숙제 마감 임박 · 피드백 등록 · 미제출 자동 알림 · notifications 컬렉션 연동 |
| 7단계 | 유튜브 영상 + 파일럿 테스트 | oEmbed 썸네일 · 비공개 링크 경고 · 강제 업데이트 체크 · Crashlytics 연동 · 실제 학원 운영 시작 |

## 11. 웹 대시보드 스펙 (admin 전용)

원장님이 PC 브라우저에서 앱 없이 학원 전체를 관리할 수 있는 전용 웹 서비스.
앱과 동일한 Firebase를 공유하므로 데이터가 실시간으로 동기화됨.

### 주요 화면 구성

**1. 홈 대시보드**
- 오늘 전체 출결 현황 (출석·지각·결석·미입력 수)
- 반별 이번 달 출석률 막대 차트
- 최근 7일 출결 추이 그래프 (Recharts)
- 오늘 결석·미입력 학생 목록
- 구독 현황 요약 (플랜·학생 수·갱신일)

**2. 출결 관리**
- 전체 반 출결 현황 한눈에 보기 (날짜별 필터)
- 월별 출결 엑셀 다운로드 — 반별 선택 또는 전체 일괄
- 결석 사유 목록 조회

**3. 학생·반 관리**
- 학생 목록 테이블 (검색·필터·정렬·반 변경)
- 학생 개별 등록
- 엑셀 일괄 업로드 — 양식 다운로드 → 작성 → 업로드 → 미리보기 확인 → 일괄 등록
- 반 생성·수정·삭제
- 학생 비활성화 (퇴원 처리)

**4. 선생님 계정 관리**
- 선생님 목록 + 담당반 현황 (`assigned_class_ids` 기반 표시)
- 학원코드 공유 또는 초대 링크 발송
- 계정 삭제

**5. 공지사항 관리**
- 공지 작성·수정·삭제
- 읽음 현황 및 미읽음 학생 목록 확인

**6. 구독·수익 관리**
- 현재 플랜 확인 (free / trial / pro) 및 학생 수
- 웹 직접 결제 — 카드/계좌, 수수료 2~3% (앱 인앱결제 30% 대비 절감)
- 결제 내역 조회

### 엑셀 일괄 업로드 스펙

| 항목 | 내용 |
|------|------|
| 업로드 양식 | 학원 웹에서 템플릿 엑셀 다운로드 제공 |
| 양식 필수 컬럼 | 이름 / 생년월일 / 보호자 연락처 / 반 이름 / 수강 시작일 |
| 파싱 라이브러리 | SheetJS — 앱과 동일 |
| 유효성 검사 | 필수값 누락·번호 형식 오류 행 하이라이트 후 표시 |
| 미리보기 | 업로드 후 등록 전 테이블로 확인 |
| 일괄 등록 | Firebase Auth 계정 생성 + Firestore users 문서 일괄 생성 |
| 완료 리포트 | 성공 N명 / 실패 N명 + 실패 사유 표시 |

### 웹 로그인 지원 범위

| 제공자 | 지원 여부 및 비고 |
|--------|----------------|
| 이메일/비밀번호 | 지원 |
| 카카오 | 지원 (Cloud Functions 동일 사용) |
| Google | 지원 |
| Apple | 웹 미지원 — iOS 전용 정책 |

### 웹 개발 순서

| 단계 | 내용 |
|------|------|
| 웹 1단계 | 프로젝트 세팅 + Firebase 연동 + 로그인 (이메일·카카오·Google) |
| 웹 2단계 | 홈 대시보드 — 출결 현황·차트·구독 요약 |
| 웹 3단계 | 학생·반 관리 + 엑셀 일괄 업로드 |
| 웹 4단계 | 출결 관리 + 월별 엑셀 다운로드 |
| 웹 5단계 | 선생님 관리·공지사항·구독 결제 |

> 웹은 앱 1~4단계 완성 후 개발 시작 권장. Firestore 구조가 확정되어야 웹에서 안정적으로 연동 가능.
> 앱과 코드 분리 — 별도 Git 레포 또는 모노레포(apps/app, apps/web) 구조 권장

### 수익 모델 연계

- 웹 직접 결제 제공 — 앱 인앱결제(30%) 대비 수수료 대폭 절감 (카드 2~3%)
- 앱 내에서 웹 결제 페이지로 유도하는 것은 앱스토어 정책 위반 — 원장님이 직접 웹에 접속해 결제하는 방식으로 운영
- Pro 플랜 가입 시 웹 대시보드 접근 가능 (무료 플랜은 앱 전용)

## 13. 인프라 운영 정책

### 앱 버전 관리 / 강제 업데이트

Firestore `app_config/version` 문서로 버전 체크 관리.

| 항목 | 내용 |

### 데이터 백업 정책

## 부록. 폴더 구조 참고

```
app/(auth)/         # 로그인 전 화면 (로그인, 회원가입)
app/(app)/
  admin/            # 원장 전용 화면
  teacher/          # 선생님 전용 화면
  student/          # 학생 전용 화면
  parent/           # 학부모 전용 화면
lib/
  firebase.ts       # Firebase 초기화 (단일 파일)
store/              # Zustand 전역 상태
types/
  index.ts          # 전체 TypeScript 타입 정의
constants/
  strings.ts        # 모든 UI 텍스트 (하드코딩 금지)
components/         # 재사용 가능한 공통 컴포넌트
```

**환경변수 규칙:**
- 모든 환경변수는 `.env.local`에서 관리 — 코드에 키 하드코딩 금지
- `EXPO_PUBLIC_` 접두사 없는 환경변수는 앱에서 읽히지 않음
- 카카오 Admin Key는 Cloud Functions 환경변수에만 저장
